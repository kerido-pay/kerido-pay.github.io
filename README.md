# kerido — презентационный сайт

Статический сайт без сборки и зависимостей. Полный лендинг и страница выбора Boost находятся в `dist/`; их нужно размещать на хостинге, разрешающем коммерческий сайт.

Корневой `index.html` — отдельная информационная страница проекта для GitHub Pages с бесплатной загрузкой Lite, без продажи подписок. `_config.yml` исключает `dist/` и внутренние документы из публикации Pages.

## Локальный просмотр

Из папки проекта: `python -m http.server 4173 --directory dist --bind 127.0.0.1`

Откройте `http://127.0.0.1:4173`. Для проверки на устройстве используйте обычный статический хостинг с HTTPS.

## Содержимое

- `dist/index.html` — лендинг, реальные снимки интерфейса, модули, тарифы, FAQ и загрузка установщика.
- `dist/app.js` — вкладки, сроки Boost, переход к оформлению, мобильное меню.
- `dist/checkout.html` и `dist/checkout.js` — страница выбора Boost с параметрами тарифа и публичного ID аккаунта. Приём оплаты закрыт.
- `dist/styles.css` — адаптивное оформление. Шрифт Manrope загружается через Google Fonts; есть системный fallback.
- `dist/documents.html` — проекты условий, конфиденциальности, предоставления доступа и возврата; контакты.
- `dist/downloads/kerido-2.1.3-setup-x64.exe` — установщик текущей сборки.
- `PAYMENT-HANDOFF.md` — описание перехода из приложения и оставшихся задач по серверной оплате.

## До платных продаж и модерации Robokassa

1. Заполнить ФИО самозанятого, ИНН и адрес для корреспонденции. Подтвердить почту поддержки.
2. Утвердить окончательную лицензионную оферту и политику данных с реквизитами продавца/оператора, сроками предоставления доступа, обращений и хранения данных.
3. Реализовать и проверить серверную интеграцию Robokassa и выдачу Boost по ID. Секретные пароли Robokassa хранить только на сервере.
4. После подключения связать страницу выбора Boost с серверным созданием заказа и обновить статусы. Сейчас сайт честно сообщает, что оплата закрыта.
5. Выложить на доступный модератору хостинг и проверить прямые ссылки, документы и установщик.

## GitHub

Репозиторий сайта изолирован от исходников десктопного приложения: `https://github.com/kerido-pay/kerido-pay.github.io`. Аккаунт проекта — `kerido-pay`.

Имя репозитория соответствует адресу пользовательского сайта `https://kerido-pay.github.io`. В этом новом репозитории GitHub автоматически включил Pages с источником main/(root). Корневая информационная страница и исключения отделяют её от полного продающего лендинга. Логин `kerido` уже занят другим пользователем (проверено 16.11.2026).

GitHub Pages запрещает использование как бесплатного хостинга для онлайн-бизнеса и сайтов, основная цель которых — коммерческие платежи. Поэтому лендинг продаж Boost для Robokassa следует размещать на подходящем другом хостинге. Исходники можно хранить в GitHub. Не включать авторазвёртывание Pages коммерческого лендинга без решения по этим ограничениям.

Официальные требования:
- https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits
- https://robokassa.com/offers/podg2.php

Логины и пароли не хранятся в коде сайта, README или конфигурации.
