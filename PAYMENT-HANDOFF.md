# Приложение → сайт → Robokassa

Подтверждённое владельцем поведение: покупка начинается в kerido, браузер открывает сайт, оплата проводится через Robokassa, сервер выдаёт Boost тому же аккаунту.

## Подготовленная часть

Страница `dist/checkout.html` принимает параметры:

`https://<домен-сайта>/checkout.html?plan=boost_7d&account=12345`

- `plan`: `boost_3d`, `boost_7d`, `boost_30d`.
- `account`: публичный ID из пяти цифр, первая не ноль.
- Только выбранный тариф и публичный ID. Нельзя передавать пароль, access/refresh token, service-role key и платёжные секреты в URL.
- Цена из URL не принимается: интерфейс использует фиксированный каталог. Перед реальной оплатой цену и срок обязательно определяет сервер, независимо от HTML/JS.
- ID проверяется только по формату. Проверка существования аккаунта и создание заказа пока не реализованы.
- Переход с лендинга сохраняет выбранный срок. Из приложения должен приходить ID текущего аккаунта.
- Продажи закрыты. Форма не отправляет запросы, кнопка оплаты недоступна, доступ не выдаётся. Никакой имитации оплаченного заказа.

## Что потребуется для запуска

1. Хостинг, разрешающий коммерческий лендинг, и окончательный HTTPS-домен. GitHub используем для исходников; ограничения Pages не подходят для этого платёжного сценария.
2. Утверждённые реквизиты самозанятого, оферта/политика и точные сроки выдачи/возврата.
3. Подключённый магазин Robokassa. MerchantLogin можно указывать в конфигурации сервера; пароли №1/№2, включая тестовые, вводятся только в секреты сервера, не в чат и не в статические файлы.
4. Сервер создаёт заказ, связывает его с аккаунтом/тарифом и считает сумму, затем подписывает переход в Robokassa. Перед этим проверяет существование аккаунта; запуск из приложения можно дополнительно связывать с короткоживущим одноразовым токеном оформления.
5. Серверный ResultURL проверяет подпись, сумму, валюту, заказ и статус. Выдача/продление Boost идемпотентна. Страница SuccessURL сама по себе доступ не выдаёт.
6. Настроить чеки для выбранного режима самозанятого и проверить тестовые успешные, неуспешные, повторные и поддельные уведомления. Только после этого включать приём оплаты.
7. Прописать рабочий домен в приложении и собрать обновлённый установщик. Сборка 2.1.3 пока сохраняет прежний информационный выбор сроков; не направляем её на выдуманный или неподходящий домен.
